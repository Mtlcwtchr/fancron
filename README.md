# Worldbuilder Atlas

Клиентское веб-приложение для ворлдбилдеров: векторная карта фэнтези-мира с тематическими
слоями (в духе Azgaar's Fantasy Map Generator) плюс редактируемый исторический таймлайн со
сменой границ во времени (в духе GeaCron). Границы — не квадраты и не картинка: это векторные
области, которые рисуются кистью и правятся по вершинам.

**Инструмент и данные разделены.** Инструмент — статический бандл (`dist/`), который кладётся
на GitHub Pages и живёт там без обслуживания. Мир — файл пользователя (`.zip` с JSON/GeoJSON
внутри), который он грузит и сохраняет вручную и хранит где хочет: диск, git-репозиторий, облако.
Ни бэкенда, ни базы, ни аккаунтов. Ничего не уходит из браузера, кроме явного экспорта.

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc --noEmit && vite build -> dist/
npm run preview  # локальная проверка собранного dist/
```

`vite.config.ts` использует `base: './'`, поэтому один и тот же `dist/` работает и на
`user.github.io/repo/`, и на любом другом статическом хостинге, и с локального диска.
В `.github/workflows/deploy.yml` лежит готовый пайплайн деплоя на GitHub Pages
(включите Pages → Source: GitHub Actions).

## Новая карта с нуля

Кнопка **«Новая карта…»** создаёт пустой мир заданного размера: ширина и высота в градусах,
детализация (число ячеек — от него зависит толщина деталей и скорость правок) и стартовый
рельеф: «несколько континентов», «всё океан» или «всё суша». Сетка ячеек создаётся сразу —
без неё не работают кисти, потому что все инструменты правят атрибуты ячеек. Дальше рельеф
лепится инструментом «Рельеф», границы и тематика — кистями, регионы появляются по мере
рисования политики.

## Карта и слои

Одна общая проекция (`d3-geo`: equirectangular / mercator / naturalEarth) и один общий zoom/pan
(`d3-zoom`) на все слои. Слои включаются независимо:

| Слой | Источник данных | Как рисуется |
|---|---|---|
| Рельеф (heightmap) | растровая сетка `layers/heightmap.json` либо `height` у ячеек | canvas |
| Температура | `temperature` у ячеек (результат симуляции) | canvas |
| Осадки | `precipitation` у ячеек (результат симуляции) | canvas |
| Ветра / климат | `layers/winds.json` (векторы или широтные полосы) | линии тока на отдельном canvas поверх слоёв |
| Морские течения | `layers/currents.geojson` (результат симуляции) | линии со стрелками: тёплые оранжевые, холодные голубые |
| Биомы | `biome` у ячеек | области с общим контуром |
| Культуры / Религии / Языки | `cultureId` / `religionId` / `languageId` у ячеек либо готовые GeoJSON-ареалы | области с общим контуром |
| Государства (политика) | регионы + таймлайн | области с общим контуром |
| Границы регионов | `regionId` у ячеек | пунктирный контур |
| Зоны (события) | `layers/zones.geojson` | полупрозрачная заливка с пунктиром |
| Реки | `layers/rivers.geojson` | линии, толщина по расходу воды |
| Дороги и пути | `layers/routes.geojson` | линии со тёмной подложкой: дороги, тропы, морские пути |
| Города и метки | `points/burgs.json`, `points/markers.json` | точки с попапом |
| Сетка ячеек | геометрия ячеек | тонкая сетка (удобно при рисовании) |

**Ветра рисуются линиями тока.** Из каждой затравки поле интегрируется шагами: на каждом шаге
берётся направление в текущей точке, и точка сдвигается по нему, поэтому поток плавно
заворачивает. Направление между широтными полосами интерполируется по короткой дуге — иначе на
границе полосы ветер скачет ступенькой (это же сглаживание использует и симуляция осадков).
Затравки стоят на решётке в градусах, а не на экране, поэтому при панораме потоки не «плывут»;
рисуются они на отдельном canvas поверх тематических слоёв, иначе их закрывают залитые области.

**Откуда берутся гибкие границы.** Ячейки — это нерегулярная сетка Voronoi (своя у демо-мира,
родная при импорте из FMG). Соседние ячейки с одинаковым значением атрибута «растворяются»
(dissolve): общие рёбра взаимно уничтожаются, остаётся один контур на область, который можно
сгладить (Чайкин, ползунок «Сглаживание границ» 0–3). Поэтому 4760 ячеек Azgaar превращаются в
21 государственную область с настоящими границами — и рисуются быстро, и выглядят как атлас.

Слой до 1500 фич рисуется SVG-путями, выше — на canvas с отсечением невидимых ячеек. Подписи
государств и мелкие города появляются по мере приближения, чтобы карта не зарастала текстом.

## Симуляция ландшафта

Раздел «Симуляция ландшафта» в сайдбаре считает мир как модель, а не рисует красивый шум.
Пять этапов, каждый включается отдельно:

1. **Рельеф.** Два режима на выбор.

   *Сохранять берега* (по умолчанию) — море остаётся морем, суша сушей, заново лепится только
   рельеф внутри материков: считается расстояние от берега (внутренние области выше), по
   коллизиям плит поднимаются хребты, а если границы плит не попали на сушу, хребты
   синтезируются «прогулками» по материку — иначе остров вышел бы идеально плоским. Береговая
   линия при этом не сдвигается ни на ячейку, включая проходы эрозии.

   *С нуля* — ячейки делятся на плиты, у каждой свой дрейф и характер (континентальная или
   океаническая). На сближающихся границах вырастают хребты, на расходящихся — рифты; сверху
   ложится многомасштабный шум прямо по сетке, затем сглаживание. У краёв карты рельеф плавно
   уводится под воду (ползунок «Отступ океана от краёв»), чтобы материки не упирались в рамку и
   не выглядели обрезанными. Высоты нормируются под заданную долю моря.
2. **Климат.** Температура — из расстояния до экватора и высоты (около 6 °C на километр).

   Осадки — переносом влаги по ветрам, и горы в этом переносе работают как стена. Вклад каждой
   наветренной ячейки взвешивается по тому, насколько она **прямо по ветру** (квадрат косинуса
   отклонения) — без этого веса воздух обтекает хребет боком и никакой тени не получается.
   На подъёме влага выпадает с насыщением по перепаду высоты (масштаб подъёма берётся от
   реального перепада мира, поэтому модель одинаково работает и для шкалы 0..100, и для метров),
   но не больше 55% за одну ячейку — иначе первый же уступ у берега осушает материк целиком.
   На подветренном склоне осадки давятся вчетверо (фён), за высоким хребтом остаток влаги
   срезается ещё на 40%, а испарение с суши понемногу возвращает влагу — материковая
   рециркуляция, без неё вся внутренняя часть континента остаётся абсолютно сухой.

   Проверка на контрольном рельефе (океан на западе, меридиональный хребет, ветер строго на восток):

   | Полоса | Осадки | Преобладающий биом |
   |---|---|---|
   | наветренная равнина | 0.0288 | степь |
   | наветренный склон | 0.0295 | влажный лес |
   | гребень | 0.0020 | ледник (высота) |
   | сразу за хребтом | 0.0008 | **холодная пустыня** |
   | дальше по ветру | 0.0054 | степь |
   | у восточного края | 0.0073 | широколиственный лес |

   То есть дождь снимается на подъёме, сразу за гребнем начинается пустыня, а вглубь материка
   влажность частично восстанавливается — как в действительности.

   Экватор не обязан лежать на широте 0 — карта может быть куском мира. Три ползунка в том же
   разделе задают **широту экватора** и температуры на экваторе и полюсе; они хранятся в
   `meta.climate` и действуют сразу: вместе с тепловым поясом сдвигаются ветровые полосы, а
   значит и дождевая тень с пустынями. Слой «Ветра» показывает результат немедленно.
3. **Течения.** Ветер тянет поверхностную воду, Кориолис отклоняет перенос вправо в северном
   полушарии и влево в южном (перенос Экмана), затем поле несколько раз расслабляется по соседям
   и «прижимается» к берегам: составляющая, направленная в сушу, убирается, поэтому вдоль
   материков поток идёт вдоль берега и замыкается в круговороты. Течение, уходящее от экватора,
   несёт тёплую воду, идущее к экватору — холодную; поправка к температуре воды доходит до
   ±4 °C и вдвое слабее передаётся прибрежной суше. Через испарение это меняет осадки:
   у холодного течения воздух сухой, и по ветру от него появляется прибрежная пустыня.
4. **Гидрология.** Впадины заливаются алгоритмом priority-flood — получаются озёра с
   естественным стоком, а не «дыры» без выхода. Сток аккумулируется вниз по склону, и где
   расход переходит порог, появляется река; ширина — от расхода, притоки сходятся в узлах.
   Опциональная речная эрозия срезает склоны пропорционально расходу, после чего вода
   пересчитывается по новому рельефу.
5. **Биомы.** Таблица в духе Уиттекера по температуре и **относительной** влажности
   (перцентиль по суше — абсолютная шкала зависит от размера карты и на одном мире дала бы
   сплошную пустыню, на другом джунгли), плюс озёра, болота и ледники.

### Настройка ветров

Раздел «Ветра и течения» правит широтные полосы напрямую: у каждой полосы свой ползунок
направления, стрелка-подсказка и подписанный диапазон широт (он сдвигается вместе с экватором).
Есть пресеты «Как в Azgaar» и «Все западные», можно добавить или убрать полосу, а кнопка
«Пересчитать климат» прогоняет течения, температуру и осадки по новым ветрам, не трогая рельеф.
Если в мире заданы явные векторы ветра, панель предложит перейти на полосы.

Осадки действительно зависят от ветров, и это проверяемо. На одном и том же рельефе:

| Ветер | Осадки на западе | Осадки на востоке |
|---|---|---|
| строго на восток (90°) | 0.0206 | 0.0091 |
| строго на запад (270°) | 0.0145 | 0.0198 |

То есть дождь достаётся наветренной стороне, а за хребтами остаётся сухо — при развороте ветров
картина зеркально меняется.

Три типичных сценария:

* **Мир с нуля**: «Новая карта…» → «всё океан» → все четыре этапа, «Сохранять берега» снять.
  На 6000 ячейках прогон занимает около 0,2 с и даёт материк целиком внутри кадра (суши у самой
  рамки — ноль ячеек), хребты вдоль коллизий, 330 рек и широтные пояса биомов.
* **Горы по готовым берегам**: оставить «Сохранять берега». На импортированной карте Azgaar
  (4760 ячеек, ~0,45 с) береговая линия не изменилась вообще (3298 ячеек суши до и после),
  максимальная высота выросла с 51 до 93, добавились 486 рек и 53 озера.
* **Только реки и климат**: снять «Рельеф» и «Пересобрать биомы» — на той же карте 4 реки
  превратились в 236, высоты, биомы и растровая сетка остались нетронутыми.

Пример полного прогона на 6000 ячеек: 9 плит, 61 течение (31 тёплое, 30 холодных), поправка
температуры воды до ±4,3 °C, 292 реки, 5 озёр — всё вместе около 0,2 с.

Симуляция — одна запись в истории, отменяется целиком через Ctrl+Z. Результат пишется в базовую
карту (не в эпоху), а растровая сетка высот удаляется только если рельеф действительно менялся.
Модель сознательно упрощённая: это не гидрологический расчёт, а генератор правдоподобной
географии, которую дальше доводят кистями.

## Редакторы

Панель «Редактор» в сайдбаре, горячие клавиши `1`–`6`, размер кисти — `[` и `]`.
В режимах правки левая кнопка занята инструментом, панорама — средней кнопкой или с Shift.

**Кисть (`2`)** красит атрибуты ячеек: биом, культуру, религию, язык, регион, государство.
Значения берутся из справочников, рядом кнопки «+ создать» / «+ регион» / «+ государство».

* *Государство* — закрашенные ячейки достаются выбранному государству **в текущей эпохе**.
  Если задета лишь часть региона, он автоматически разрезается: новый регион наследует
  владельцев старого во всех прочих эпохах, поэтому прошлое не «плывёт». Регионы, созданные
  кистью и имеющие одинаковую историю, склеиваются обратно — их число не разрастается.
* *Регион* — переносит ячейки в выбранный регион; так и двигаются его границы. Значение
  «без региона» делает ячейки ничейными: они выпадают и из региона, и из государства.
* *Биом / культура / религия / язык* — обычная покраска ареалов.

**Выбор объектов.** Клик по карте выбирает регион (или ячейку), **Alt+клик** — государство,
которому регион принадлежит в текущей эпохе; клик по строке в списке государств тоже выбирает
государство, а кнопка ✎ в строке берёт его кистью. У выбранного государства правая панель
показывает имя (и имя на текущий момент, если было переименование), цвет, сколько у него сейчас
регионов и ячеек, число переименований и переходов, а его территория подсвечивается на карте.

**Регион ↔ государство.** В панели государства кнопка «+ регион с этим именем» создаёт регион с
тем же названием, сразу закрепляет его за этим государством в текущей эпохе и включает кисть
региона — остаётся закрасить. Обратная кнопка в панели региона, «+ государство с этим именем»,
создаёт державу по названию региона и отдаёт ей этот регион в текущей эпохе. В обеих панелях
рядом лежат «Кисть этим регионом/государством» и «Удалить», так что выбранный объект правится
и стирается на месте.

В разделах «Государства» и «Регионы» есть кнопка **«Очистить всё»** с модальным подтверждением:
окно показывает, сколько объектов будет удалено и что при этом останется. Очистка государств
обнуляет политику во всех эпохах, но оставляет регионы и географию; очистка регионов снимает у
ячеек принадлежность региону — и базовую, и эпохальные правки. Если регионов больше пятидесяти,
для подтверждения нужно ввести слово «очистить». Обе операции — одна запись в истории и
отменяются через Ctrl+Z.

**Обрезать края** (кнопка рядом с кистью государства и в разделе «Государства») подчищает
политическую карту в текущей эпохе: снимает принадлежность с закрашенной воды и с ячеек,
у которых почти нет соседей того же владельца — то есть с одиночных вкраплений и тонких
языков, которые остаются, когда кисть прошла мимо региона. Это одна операция в истории;
на карте из Azgaar один клик снимает сотню лишних ячеек.

**Рельеф (`3`)** — кисти высот: `Поднять`, `Опустить`, `Выровнять` (тянет к средней высоте под
кистью), `Размыть` (усредняет по соседям), `Берег` (чистит береговую линию: убирает одинокие
острова и лагуны). Сила и размер — ползунками. Биом автоматически согласуется с уровнем моря:
поднятая из моря земля перестаёт быть «Marine», затопленная — становится морем. Если у мира была
растровая сетка высот, при первой правке она заменяется рельефом по ячейкам.

**Точки (`4`)** — города и метки. Клик по карте ставит объект, перетаскивание существующего
переносит его. Название, население, флаги «столица» и «порт» (у города) или значок, тип и
заметка (у метки) правятся в правой панели, там же кнопка удаления. Значок метки выбирается
из набора или вводится вручную — годится любой символ или эмодзи.

**Города и метки живут во времени.** У каждой точки есть даты «существует с» и «исчезает с»:
вне этого отрезка её на карте просто нет, а счётчик в списке слоёв показывает, сколько объектов
есть **сейчас**. Кнопки «Основать с этой эпохи» и «Разрушить с этой эпохи» ставят текущую дату
одним нажатием, «Существует всегда» очищает обе. Город, поставленный в мире с несколькими
эпохами, автоматически основывается текущей датой — в прошлом его быть не должно.
Переименования работают как у государств и регионов: кнопка ⏱ открывает историю названий, и
подпись на карте показывает имя, действовавшее на выбранный момент.

**Маршрут (`5`)** — дороги, тропы и морские пути. Клик ставит опорную точку, а путь между
опорами прокладывается сам по ячейкам алгоритмом A*: дорога держится суши и обходит горы
(подъём удорожает ячейку, вода проходима, но в девять раз дороже — узкий пролив пересечь можно,
крюк через океан не выйдет), морской путь идёт только по воде и честно сообщает, что через
материк не проложится. `Enter` — завершить, `Backspace` — убрать последнюю опору, `Esc` —
отменить. Готовые маршруты перечислены тут же: двойной клик переименовывает, ✕ удаляет.

**Вершины (`6`)** — для регионов с собственной геометрией (`regionSource: 'geometry'`): тянуть
вершины, клик по границе вставляет вершину, Alt+клик по вершине удаляет. Для миров, где регионы
собраны из ячеек, границы двигаются кистью «Регион» — инструмент подскажет об этом сам.

Любая правка попадает в undo/redo (`Ctrl+Z` / `Ctrl+Shift+Z`, 40 шагов); один мазок кисти — одна
запись в истории. Черновик пишется в IndexedDB и предлагается к восстановлению при следующем
открытии — это не замена экспорту, а защита от случайной перезагрузки вкладки.

Прочие горячие клавиши: `Ctrl/Cmd+S` — экспорт архива, `Esc` — вернуться к инструменту «Выбор».
Маршруты и точки, как и всё остальное, попадают в общую историю правок.

## Названия, переименования и переходы

Кнопка **«Названия и переходы…»** открывает менеджер всех имён мира: государства, регионы,
культуры, религии, языки, города, метки. В нём можно править названия «на всю карту» —
списком, с фильтром и массовой заменой подстроки (например, `Kingdom of` → `Королевство`).

У каждой сущности есть две истории:

* **Переименования** — «с даты D зовётся так». Карта, легенда и подписи всегда показывают имя,
  действовавшее на текущий момент шкалы: одна и та же страна называется «Древняя Империя» до
  -600 и «Срединная Империя» после.
* **Переходы** — «с даты D вместо этой сущности показывается другая». Так описывается смена
  режима (Империя → Республика) и эволюция языков, культур, религий: язык-предок после даты
  перехода отображается как язык-потомок, а территории двух государств сливаются в одно, не
  требуя перекраски карты. Переходы идут по цепочке, поэтому «древний → средний → современный»
  работает само.

## Таймлайн

Модель как в GeaCron: один и тот же набор регионов в разные эпохи принадлежит разным
государствам. Данные — список snapshot'ов (`дата → { regionId: stateId }`) и список событий.
Перетаскивание ползунка перерисовывает политический слой под ближайший snapshot слева (без
интерполяции геометрии — намеренно, см. «вне скоупа»). Можно добавить эпоху на произвольную дату
(копируется с предыдущей), менять владельца региона списком в правой панели (там же вся его
история), создавать и править события с привязкой к региону.

Даты — произвольные строки своей эры (`-1200`, `570 HE`, `Год Пепла 34`); для шкалы из строки
берётся первое число, подписи эр настраиваются в `meta.era`.

### География и регионы по эпохам

Политика меняется во времени по определению, но и сама земля со временем меняется: залив
затопило, степь стала пустыней, культура сменилась, провинция разрослась. Для этого у каждой
эпохи есть **гео-правки** (`snapshot.geo`) — точечные оверрайды атрибутов ячеек: высота, биом,
культура, религия, язык и **регион**.

Регионы не статичны: `snapshot.geo[cellId].regionId` переносит ячейку в другой регион начиная
с этой эпохи, поэтому границы провинций живут во времени так же, как принадлежность государствам.
Кисть государства в режиме эпохи не режет базовую карту, а создаёт «эпохальный» регион
(`Кадешское царство · Год Договора`) и переселяет в него закрашенные ячейки — один регион на
государство за эпоху, а не гора осколков. В списке регионов рядом с именем стоит число ячеек
**в текущей эпохе**; пустые в этой эпохе показаны бледнее.

У политики и географии разные умолчания, и переключатель в панели «Редактор» показывает тот,
что относится к текущей кисти:

* **государства и регионы** правятся **только с текущей эпохи** — галочка «Менять только с этой
  эпохи» включена по умолчанию. Прошлые эпохи не меняются задним числом, а базовая карта остаётся
  нетронутой; «Обрезать края» работает так же. Снимите галочку, если действительно нужно
  переписать границы во всех эпохах сразу;
* **рельеф, биомы, культуры, религии, языки** по умолчанию правятся в базовой карте (то есть во
  всех эпохах) — это лепка самого мира. Галочка «Правки → в текущую эпоху» переводит их в
  эпохальный режим: «с этой даты здесь залив/пустыня». Правила простые и те же, что у
принадлежности регионов: правки накапливаются от древних эпох к текущей, то есть действуют
«с этой даты и дальше», а базовая карта остаётся целой. Отсюда и обратимость: кнопка
«Сбросить» убирает правки эпохи, undo работает как обычно, а хранятся только отличия
(в архиве это несколько десятков килобайт на эпоху, а не копия мира).

Растровая сетка высот при правках эпохи не удаляется: она описывает базовый рельеф, который
никуда не делся. При правке базовой карты — удаляется, потому что перестала бы соответствовать.

## Импорт

Файлы можно перетащить прямо в окно или выбрать кнопками в сайдбаре. Порядок распознавания:
`.zip` → полный JSON FMG → дамп внутренней модели → GIS-экспорт GeoJSON и CSV.

**Полный JSON Azgaar FMG** (Export → JSON → Full) — предпочтительный путь: внутри лежит вся
модель FMG, поэтому переносится максимум данных.

* `pack.cells` + `pack.vertices` → настоящая сетка Voronoi (родные органические границы);
  высоты, биомы, культуры, религии, государства, провинции, население;
* `pack.states` / `provinces` / `cultures` / `religions` → справочники с именами и цветами;
  провинции становятся регионами таймлайна, `nameBases` — языковыми семьями;
* `pack.burgs` / `pack.markers` (+ `notes`) → города и метки с описаниями;
* `pack.rivers` → реки (линия по центрам ячеек), `pack.routes` → дороги, тропы и морские пути,
  `pack.zones` → зоны (геометрия собирается из ячеек тем же растворением границ);
* `grid.cells[].h` → растровая сетка высот;
* `settings.options` → ветра, год и название эры (стартовый snapshot ставится на текущий год);
* военные кампании государств → готовые события на шкале времени.

Пиксельные координаты FMG переводятся в градусы через `mapCoordinates` — так же, как это делает
сам FMG при GIS-экспорте.

**GIS data export (GeoJSON)** — `*_cells.geojson`, `*_provinces.geojson`, `*_states.geojson`,
`*_burgs.geojson`, `*_markers.geojson`, `*_rivers.geojson`, `*_routes.geojson`; высоты вида
«1148 m» приводятся к числам, индекс биома — к имени из палитры FMG.

**CSV-таблицы** — `burgs.csv` (координаты берутся из `Latitude`/`Longitude`; если есть только
пиксельные `x`/`y`, они линейно натягиваются на bbox ячеек — задокументированное приближение),
`states.csv`, `cultures.csv` (плюс `Namesbase` → языковая семья), `religions.csv`, `provinces.csv`.

Родной формат `.map` не читается — приложение прямо скажет об этом и предложит JSON или GIS-экспорт.

### Импорт с картинки (SVG / PNG)

Кнопка **«Импорт картинки (SVG/PNG)»** или перетаскивание файла. Пути разные, потому что
источники разной природы:

* **SVG — вектор, два режима.**
  *По фигурам*: обходятся все залитые фигуры (`path`, `polygon`, `rect`, `circle`, …), контур
  снимается через `getPointAtLength`, поэтому кривые Безье переносятся корректно; учитываются
  трансформации групп. Фигура становится регионом со своей геометрией, фигуры одного цвета
  заливки — одним государством, имя берётся из `<title>`, `inkscape:label` или `id`. Фоновый
  прямоугольник (>85% холста) отбрасывается. Такие регионы правятся инструментом «Вершины».
  Кроме политики фигуры можно импортировать как зоны или ареалы культур/религий/языков.
  *По нарисованным границам*: для карт, где границы — это обводки без заливки. Документ
  отрисовывается браузером дважды: как чистая линейная графика (все заливки сняты, обводки
  почернены и утолщены через `!important`, подписи убраны) — по ней ищутся замкнутые области, —
  и как есть, чтобы взять цвет каждой области. Обводки залитых фигур тоже работают как границы,
  а бесцветная линейная графика получает цвета из палитры.
* **PNG/JPG — растр.** Поверх картинки кладётся нерегулярная сетка Voronoi (детализация
  задаётся числом ячеек), в центре каждой ячейки берётся цвет. Дальше три режима:

  * *рельеф по яркости* — светлее значит выше, уровень моря 20, биомы расставляются по высоте
    и широте, попутно сохраняется растровая сетка высот;
  * *цветовые группы* — цвета кластеризуются (k-means с разведением центров по цветовому
    пространству), самая «синяя» крупная группа считается морем, остальные становятся
    государствами, культурами, религиями, языками или биомами. Мелкие группы, возникающие на
    антиалиасных границах, раздаются соседям;
  * *по нарисованным границам* — для карт, где границы прочерчены линиями. Строится маска
    линий (тёмные пиксели по настраиваемому порогу плюс резкие перепады по Собелю), затем
    заливкой ищутся замкнутые области; каждая область становится группой со своим средним
    цветом, внешняя область (та, что касается рамки) принимается за море, крапинки-шум
    отбрасываются. Ячейки, чей центр попал прямо на линию, получают ближайшую область.
    Так рисунок с обведёнными провинциями превращается в готовую политическую карту.

Растровый разбор — это оценка по пикселям, а не векторизация: на границах остаются артефакты,
зато мир сразу получается редактируемым — кисти и «Обрезать края» доводят его за минуту.

Формат экспорта Azgaar: <https://github.com/Azgaar/Fantasy-Map-Generator/wiki/GIS-data-export>

## Формат архива мира

Обычный zip, который можно править руками и держать в git:

```
meta.json                     { name, createdAt, updatedAt, schemaVersion, projection, era, seaLevel, regionSource,
                                climate: { equatorLat, temperatureEquator, temperaturePole } }
map.geojson                   FeatureCollection ячеек: id, height, biome, cultureId, religionId, languageId,
                              stateId, provinceId, regionId (+ temperature, precipitation, flux, lake от симуляции)
regions.geojson               базовая геометрия регионов: id, name, stateId (+ auto/epoch у созданных кистью);
                              границы по эпохам лежат в timeline/snapshots.json -> geo[cellId].regionId
layers/heightmap.json         { width, height, bbox, values[] } — регулярная сетка высот
layers/winds.json             { bands[] } или { vectors: [{lon, lat, angle, speed}] }
layers/cultures.geojson       необязательные готовые ареалы (иначе цвет берётся из атрибутов ячеек)
layers/religions.geojson
layers/languages.geojson
layers/rivers.geojson         линии рек: name, type, width, discharge
layers/routes.geojson         линии путей: name, group (roads | trails | searoutes)
layers/zones.geojson          зоны событий: name, type, color
points/burgs.json             [{ id, name, x, y, height, population, capital, port, ... }]
points/markers.json           [{ id, name, x, y, type, icon, note }]
timeline/snapshots.json       [{ id, date, label, regionState: { regionId: stateId },
                                 geo?: { cellId: {height?, biome?, cultureId?, religionId?, languageId?, regionId?} }, notes }]
timeline/events.json          [{ id, date, title, description, regionId? }]
timeline/states.json          [{ id, name, color, names?, succeededBy? }]
dictionaries/*.json           справочники культур, религий, языков, биомов с цветами
```

Координаты точек — в той же системе, что `map.geojson` (долгота/широта). `schemaVersion` = 5;
миграции живут в `src/io/validate.ts`, архивы версий 1–4 читаются без потерь. Истории имён
(`names`) и переходов (`succeededBy`) хранятся у государств, регионов и записей справочников.

Две вещи, добавленные к исходному ТЗ, — и зачем:

* `regions.geojson` отделяет политические единицы от тематических ячеек: cell-export Azgaar даёт
  тысячи полигонов, а историю надо перекрашивать по осмысленным регионам. Если файла нет,
  регионами становятся ячейки `map.geojson`.
* `meta.regionSource` говорит, откуда геометрия регионов. `'cells'` — регион собран из ячеек
  (`cell.regionId` плюс оверрайды эпох), границы растворяются на лету и рисуются кистью;
  `'geometry'` — у региона свой полигон, его вершины можно двигать. В архив пишется базовая
  геометрия регионов, чтобы `regions.geojson` открывался в QGIS; история границ — в снапшотах.
* `meta.seaLevel` — уровень моря в единицах `height` (у Azgaar это 20 при шкале 0..100); от него
  зависят палитра рельефа, кисть «Берег» и согласование биомов.

## Архитектура

```
src/
  state/     types.ts (модель), store.ts (мини-реактивный стор), world.ts (стор мира, undo/redo,
             мазки, пер-слойные ревизии кэшей), edits.ts (правки через историю, имена, переходы),
             paint.ts (кисти, обрезка краёв), naming.ts (имена и переходы во времени),
             geoOverrides.ts (география по эпохам),
             topology.ts (кэш соседства/индексов и растворённых границ), ui.ts, time.ts
  io/        fmgFull.ts (полный JSON FMG), azgaar.ts (GIS/CSV),
             imageImport.ts (SVG, яркость, цвета, нарисованные границы),
             archive.ts (JSZip), validate.ts (нормализация + миграции),
             files.ts (input/Blob/File System Access API), draft.ts (IndexedDB),
             session.ts (действия уровня приложения)
  map/       mapView.ts (D3-рендер, зум, кисти, hit-test, ручки вершин), layers.ts (слои, легенды),
             projection.ts, colors.ts (палитры FMG)
  sim/       landform.ts (тектоника, климат, гидрология, биомы)
  timeline/  timelineView.ts (шкала, ползунок, эпохи, события)
  ui/        app.ts (каркас, drag&drop, хоткеи), sidebar.ts, inspector.ts, namesManager.ts, dialog.ts
  sample/    sampleWorld.ts (демо-мир на сетке Voronoi), newWorld.ts (пустая карта по размеру)
  util/      dissolve.ts (растворение границ + сглаживание + соседство), mesh.ts (сетка Voronoi),
             biome.ts (биом по высоте и широте), geo.ts (намотка колец), random.ts, id.ts
```

Единственный источник правды — `World` из `src/state/types.ts`. Любой импорт приводится к нему,
любая правка идёт через `commit()`/`mutateWorld()` в `src/state/world.ts`, экспорт — сериализация
этой же структуры. В dev-режиме сторы доступны из консоли как `window.__atlas` — удобно отлаживать.

Две неочевидные детали, на которые легко наступить:

* `d3-geo` считает полигоны сферическими и требует, чтобы внешнее кольцо шло **по часовой
  стрелке** — обратно соглашению RFC 7946, которого держатся Azgaar и большинство редакторов.
  Кольцо «наоборот» превращает клетку в «весь мир, кроме клетки», и карта заливается одним
  цветом. Поэтому на импорте все кольца перематываются (`src/util/geo.ts`).
* Мазок кисти не пересчитывает границы: закрашенные ячейки сразу рисуются поверх слоёв, а
  растворение и полный рендер выполняются один раз, когда кисть отпущена. Кэши инвалидируются
  по слоям, поэтому покраска культур не заставляет пересчитывать биомы и политику.

## Вне скоупа

Многопользовательский realtime, любой бэкенд/БД/аккаунты, плавная геометрическая интерполяция
границ между эпохами, честная векторизация растровой картинки (вместо неё — сетка ячеек с
сэмплированием), импорт торговли, армий и квестов из FMG. Симуляция ландшафта есть, но она
намеренно упрощённая: не претендует на физику Azgaar или настоящих ГИС-моделей.
